## 1. MỤC TIÊU (đọc trong 1 phút)

Viết **"người gác cổng"** của máy chủ: mọi API (trừ `/health` và API đăng nhập/đăng ký) phải kiểm **mỗi yêu cầu**:
1. Token (JWT) **thật** — kiểm chữ ký, người phát, hạn.
2. **Phiên còn sống** — phiên ứng dụng (`app_sessions`) chưa thu hồi/hết hạn **và** phiên Supabase Auth còn hiệu lực. JWT còn hạn **không đủ**.
3. Tài khoản đã **có username** (chưa có ⇒ phải chọn trước) và đã **xác minh email**.

Kèm API `GET /api/v1/me` trả thông tin người đang đăng nhập.

## 2. KHÁI NIỆM CẦN BIẾT

| Khái niệm | Giải thích |
|---|---|
| **JWT** | Token 3 phần `header.payload.signature`. Phần giữa đọc được bằng base64 — **ai cũng giả được** nếu chỉ decode. Phải **kiểm chữ ký** bằng khoá công khai của Supabase |
| **JWKS** | Danh sách khoá công khai Supabase đăng tại `${SUPABASE_URL}/auth/v1/.well-known/jwks.json` — dùng để kiểm chữ ký; cache lại |
| **Claim** | Trường trong JWT: `sub` (id user), `iss` (người phát), `aud` (`authenticated`), `exp` (hạn), `session_id` |
| **Global guard (NestJS)** | Chạy trước **mọi** route; route nào công khai thì gắn `@Public()` |
| **Phiên thu hồi nhưng JWT còn hạn** | JWT sống 1 giờ; người dùng đăng xuất ở phút 5 thì 55 phút còn lại token vẫn "đúng chữ ký". Guard **phải** kiểm DB mỗi lần để chặn — lỗi `F-22` lần trước: hàm kiểm phiên có mà **không ai gọi** |
| **503 khi không kiểm được** | DB/Auth lỗi ⇒ **từ chối** (503), **không** cho qua cho "tiện" |

## 5. HƯỚNG DẪN LÀM TỪNG BƯỚC

### 5.1 `jwt.service.ts`
`verify(accessToken): Promise<{ id; email; sessionId }>` — kiểm **chữ ký** bằng JWKS (thư viện `jose` 🟡), `iss`, `aud = 'authenticated'`, `exp`, `sub`; lấy `session_id`. ⛔ **Cấm** chỉ decode.

### 5.2 `auth.guard.ts` (global, bỏ qua `@Public()`)
```
① Đọc Authorization: Bearer <token>; thiếu ⇒ 401 UNAUTHENTICATED
② jwt.verify(token); sai ⇒ 401
③ private.is_auth_session_active(sessionId, userId) = false ⇒ 401
④ app_sessions theo auth_session_id: không có / revoked_at ≠ NULL / now >= idle_expires_at /
   (absolute_expires_at ≠ NULL và now >= absolute_expires_at) ⇒ 401
⑤ DB hoặc Auth lỗi khi kiểm ⇒ 503 (không cho qua, không gia hạn)
⑥ req.user = { id, email, sessionId, appSessionId }
```
`now` lấy từ `Clock` tiêm vào (để TK06.2.2 test biên bằng đồng hồ giả).

### 5.3 `onboarding.guard.ts` + email
- `profiles.username IS NULL` ⇒ 403 `ONBOARDING_REQUIRED`. Ngoại lệ: `GET /api/v1/me`, `POST /api/v1/auth/complete-profile`, `POST /api/v1/auth/logout`, route auth cần thiết.
- Email chưa xác minh (`email_confirmed_at` qua helper) ⇒ 403 `EMAIL_UNVERIFIED`.

### 5.4 `GET /api/v1/me`
Trả `{ id, username, displayName, emailVerified, hasPassword }` trong vỏ `ApiResult`. **Không** trả token, **không** trả email (🟡 — đặc tả cấm lộ email ở API khác; `/me` cũng không cần).

### 5.5 Bộ lọc lỗi toàn cục
Mọi lỗi ném `DomainError(code)` ⇒ HTTP theo `ERROR_HTTP_STATUS`, body `{ ok: false, error: { code, message }, requestId }`.

### 5.6 Log
Logger lọc header `Authorization` và mọi chuỗi giống token.

### 5.7 Test (viết TRƯỚC) — `issue-046.test.ts`
Token thật từ `authAs`; test tự tạo `app_sessions` cho token (vì API đăng nhập chưa có); ca sai chữ ký = sửa 1 ký tự phần chữ ký của token thật; ca thu hồi: dùng token thành công → thu hồi → dùng lại **cùng** token ⇒ 401.

**Thử phá:** bỏ bước ④ ⇒ ca "thu hồi phiên" phải đỏ.

### A. Chuẩn bị
1. `git pull && pnpm db:reset && pnpm dev`. Khoá publishable `PUB` từ `pnpm db:status`.
2. Tạo user **A** (có username, đã xác minh) và **B** (username NULL — tạo không có metadata `signup_username`) theo [Sổ tay §15.3](../04-HUONG-DAN-KIEM-THU.md).
3. **Lấy token thẳng từ Supabase** (API đăng nhập của app chưa có ở Task này) và **tạo phiên ứng dụng bằng SQL**:
   ```bash
   tok() { curl -s -X POST 'http://127.0.0.1:54321/auth/v1/token?grant_type=password' -H "apikey: $PUB" \
           -H 'Content-Type: application/json' -d "{\"email\":\"$1\",\"password\":\"Test@12345\"}" | jq -r .access_token; }
   TA=$(tok alice@test.local); TB=$(tok bob@test.local)
   claims() { echo "$1" | cut -d. -f2 | tr '_-' '/+' | base64 -d 2>/dev/null | jq '{sub, session_id}'; }
   claims $TA        # ghi lại sub (user id) và session_id
   ```
   Trong `psql` quản trị, cho mỗi token:
   ```sql
   insert into app_sessions (id, user_id, auth_session_id, mode, created_at, last_active_at, idle_expires_at)
   values (gen_random_uuid(), '<sub>', '<session_id>', 'REMEMBERED', now(), now(), now() + interval '30 days');
   ```
4. Lệnh gọi API: `me() { curl -s -i http://127.0.0.1:3000/api/v1/me ${1:+-H "Authorization: Bearer $1"}; }`
