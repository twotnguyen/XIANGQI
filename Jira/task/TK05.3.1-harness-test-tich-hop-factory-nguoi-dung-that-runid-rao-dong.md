**Việc cần làm:**
1. `tests/integration/setup.ts` (globalSetup của `vitest.integration.config.ts`):
   ```
   ① Parse DATABASE_URL; host phải là 127.0.0.1 hoặc localhost và tên DB đúng DB test
   ② Sai ⇒ throw TRƯỚC khi mở kết nối
   ③ Thử kết nối; thất bại ⇒ throw (KHÔNG skip)
   ④ Kiểm Supabase Auth local (GET SUPABASE_URL/auth/v1/health) — lỗi ⇒ throw
   ```
2. `tests/fixtures/integration.ts`:
   ```ts
   createTestApp(): Promise<{ app: INestApplication; baseUrl: string; dispose(): Promise<void> }>
   seedUsers(runId: string): Promise<{ A; B; S1; S2; S3; S4; S5; S6 }>  // 8 tài khoản qua Supabase Auth Admin API THẬT,
                                                                       // email `${role}.${runId}@test.local`, đã xác minh, có username
   authAs(user): Promise<{ token: string }>                            // đăng nhập thật bằng mật khẩu → access token thật
   resetTestData(runId: string): Promise<void>                         // xoá theo runId, đúng thứ tự FK; KHÔNG TRUNCATE
   withBarrier<T>(n: number, fn: (i: number) => Promise<T>): Promise<T[]> // n tác vụ chờ nhau rồi cùng lao vào điểm tranh chấp
   dbAs(role: 'app_server'): Promise<pg.PoolClient>                    // 2 kết nối riêng cho test race
   ```
3. `dispose` đóng pool, socket, listener, HTTP server — chạy cả khi test ném lỗi (`finally`/`afterAll`).
4. Test dùng role `app_server`, không superuser (superuser chỉ dùng trong `seedUsers`/`resetTestData` qua `DATABASE_ADMIN_URL`).
5. `tests/integration/harness.test.ts` tự kiểm: seed 8 user; `authAs` trả JWT verify được bằng Supabase; hai runId không lẫn; `withBarrier(2)` làm 2 transaction cùng chờ `SELECT ... FOR UPDATE` trên cùng hàng (một chờ một); `dispose` chạy khi test ném lỗi.
6. README mục "Viết test tích hợp": mẫu dùng harness, luật "thiếu DB phải đỏ", "race phải có barrier + 2 kết nối".

**Bẫy dễ gặp:** lần trước test tích hợp **luôn bị skip** suốt nhiều tháng mà CI vẫn xanh (`F-11`); test "DB" tự mock chính nó (`F-12`).
