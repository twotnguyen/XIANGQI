## 1. MỤC TIÊU (đọc trong 1 phút)

Viết **bộ công cụ test tích hợp** (harness) mọi Task Backend về sau đều dùng:
- Dựng app NestJS thật + **8 tài khoản thật** qua Supabase Auth.
- Đăng nhập thật lấy token thật.
- **Rào đồng bộ** + **2 kết nối DB riêng** để tạo tranh chấp thật.
- Mỗi lần chạy có `runId` riêng — 2 người chạy test cùng lúc không lẫn dữ liệu.
- **Thất bại ồn ào**: thiếu DB / sai địa chỉ ⇒ test **đỏ** ngay, không bao giờ "bỏ qua".

## 2. KHÁI NIỆM CẦN BIẾT

| Khái niệm | Giải thích |
|---|---|
| **Harness** | Bộ hàm dựng sẵn môi trường cho test (app, user, DB) để mỗi test không phải tự làm |
| **`globalSetup`** | Code Vitest chạy **một lần trước** mọi test — nơi kiểm DB có sống không |
| **`runId`** | Chuỗi ngẫu nhiên gắn vào email/username/dữ liệu của một lần chạy — xoá đúng dữ liệu của mình, không `TRUNCATE` cả bảng |
| **Barrier + 2 kết nối** | Xem [Từ điển](../05-TU-DIEN-KY-THUAT.md#barrier). `Promise.all` trên 1 kết nối **không** tạo tranh chấp thật |
| **`dispose` trong `finally`** | Đóng pool, socket, cổng HTTP **kể cả khi test lỗi** — không thì tiến trình treo, cổng bị chiếm |

**Lỗi lần trước:** test tích hợp **luôn bị skip** suốt nhiều tháng mà CI vẫn xanh (`F-11`); test "DB" tự mock chính nó (`F-12`).

**Từ kỹ thuật cần tra:** [Barrier](../05-TU-DIEN-KY-THUAT.md#barrier) · [Race condition](../05-TU-DIEN-KY-THUAT.md#race) · [Unit/Integration/E2E](../05-TU-DIEN-KY-THUAT.md#test-lanes) · [Test skip](../05-TU-DIEN-KY-THUAT.md#skip) · [Khoá dòng](../05-TU-DIEN-KY-THUAT.md#khoa-dong)

## 5. HƯỚNG DẪN LÀM TỪNG BƯỚC

### 5.1 `tests/integration/setup.ts` (globalSetup)
```
① Parse DATABASE_URL: host phải 127.0.0.1 hoặc localhost, tên DB đúng DB test
② Sai ⇒ throw TRƯỚC khi mở kết nối (không chờ timeout mạng)
③ Thử kết nối; thất bại ⇒ throw (KHÔNG skip)
④ GET SUPABASE_URL/auth/v1/health — lỗi ⇒ throw
```

### 5.2 `tests/fixtures/integration.ts`
```ts
createTestApp(): Promise<{ app: INestApplication; baseUrl: string; dispose(): Promise<void> }>
seedUsers(runId: string): Promise<{ A; B; C; S1; S2; S3; S4; S5; S6 }>
  // tạo qua Supabase Auth Admin API THẬT; email `${ten}.${runId}@test.local`; đã xác minh; có username `${ten}_${runId}`
authAs(user): Promise<{ token: string }>          // đăng nhập thật bằng mật khẩu → access token thật
resetTestData(runId: string): Promise<void>        // xoá dữ liệu của runId theo đúng thứ tự FK; KHÔNG TRUNCATE
withBarrier<T>(n: number, fn: (i: number) => Promise<T>): Promise<T[]>
  // n tác vụ cùng đợi ở vạch, rồi cùng lao vào điểm tranh chấp
dbAs(role: 'app_server'): Promise<pg.PoolClient>  // mỗi lần gọi = 1 kết nối riêng (dùng 2 lần cho test race)
```
- Test chạy bằng `app_server`; superuser (`DATABASE_ADMIN_URL`) **chỉ** trong `seedUsers`/`resetTestData`.
- `dispose` đóng pool, socket, listener, HTTP server — gọi trong `afterAll`/`finally`.

### 5.3 `tests/integration/harness.test.ts` — tự kiểm harness

| ID | Kiểm |
|---|---|

### 5.4 README — "Viết test tích hợp"
Mẫu dùng harness; 3 luật: thiếu DB phải đỏ; race phải có barrier + 2 kết nối; không mock DB.

**Thử phá:** đổi bước ③ thành `console.warn` + bỏ qua ⇒ chạy khi tắt DB phải thấy test **xanh giả** — xác nhận bước ③ cần thiết; hoàn lại.
