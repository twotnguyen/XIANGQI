## 1. MỤC TIÊU (đọc trong 1 phút)

Quản lý **vòng đời phiên**:
1. **Gia hạn** phiên khi người dùng **sử dụng chủ động** (mở trang, chuyển màn, gửi lệnh) — **không** gia hạn khi chỉ làm mới token / heartbeat / nhận sự kiện.
2. **Đăng xuất** thiết bị này (`CURRENT`) hoặc **mọi thiết bị** (`ALL`) — chặn token **ngay**, rồi mới báo Supabase; Supabase lỗi thì **thử lại sau** (không mất việc khi khởi động lại).

## 2. KHÁI NIỆM CẦN BIẾT

| Khái niệm | Giải thích |
|---|---|
| **Hạn nhàn rỗi (idle)** | Hết hạn nếu không dùng trong 30 ngày (REMEMBERED) / 30 phút (TEMPORARY). Mỗi lần dùng chủ động ⇒ dời ra `now + cửa sổ` |
| **Hạn tuyệt đối (absolute)** | Chỉ TEMPORARY: 12 giờ từ lúc đăng nhập — **không** bao giờ dời |
| **`now >= deadline` là hết** | Đúng tại mốc = đã hết. Viết `>` là sai 1 ms |
| **Chỉ tăng, không giảm** | 2 activity đồng thời với `now` khác nhau ⇒ giữ giá trị **lớn hơn** (`max`) |
| **Fence (hàng rào)** | Đặt `revoked_at` trong DB **trước** ⇒ guard (TK06.1.1) chặn token ngay; việc gọi Supabase làm sau |
| **Job bảo mật** | Bảng `auth_security_jobs` ghi "việc còn phải làm với Supabase"; worker thử lại tới khi xong |
| **`operationId`** | Mã do client tạo cho 1 lần đăng xuất; gửi lại cùng mã ⇒ trả kết quả cũ (không làm 2 lần) |

## 5. HƯỚNG DẪN LÀM TỪNG BƯỚC

### 5.1 Hàm tính hạn mới (thuần, dễ test)
```ts
function nextIdle(mode, now, oldIdle, absolute) {
  if (now >= oldIdle || (absolute !== null && now >= absolute)) throw EXPIRED;
  const windowMs = mode === 'REMEMBERED' ? 30 * 86_400_000 : 30 * 60_000;
  return Math.min(absolute ?? Infinity, Math.max(oldIdle, now + windowMs));
}
```

### 5.2 `appSession.touch(appSessionId)`
Trong `withTransaction`: `SELECT … FROM app_sessions WHERE id=$1 FOR UPDATE` → kiểm thu hồi/hạn → `UPDATE last_active_at = now, idle_expires_at = nextIdle(...)`.
Các service nghiệp vụ (đi cờ, chat…) ở Epic sau sẽ gọi `touch()`.

### 5.3 `POST /api/v1/auth/activity` body `{ kind: 'PAGE_VIEW' | 'NAVIGATION' }`
Client gọi khi mở trang/chuyển route ⇒ `touch()`. **Không** gia hạn khi: refresh token, heartbeat, polling, nhận sự kiện, reconnect.

### 5.4 `POST /api/v1/auth/logout` body `{ scope: 'CURRENT' | 'ALL', operationId }`
```
① Transaction:
   - Đã có job với operationId này? payload giống ⇒ trả trạng thái cũ; khác ⇒ 409 CONFLICT
   - UPDATE app_sessions SET revoked_at = now  (CURRENT: đúng auth_session_id · ALL: mọi phiên của user)
   - INSERT auth_security_jobs (reason LOGOUT, scope, target_auth_session_ids = danh sách lúc này, revocation_cutoff = now, status PENDING)
② NGOÀI transaction: gọi Supabase Admin signOut (local / global)
③ Thành công ⇒ job DONE, trả { status: 'COMPLETED' } · Lỗi ⇒ giữ fence, trả { status: 'PENDING' }
```

### 5.5 Worker `revoked-sessions.service.ts`
Hẹn giờ trong tiến trình (dùng `Scheduler` tiêm vào 🟡 mỗi 30 giây): lấy job `PENDING`/`RUNNING` quá lease → gọi lại Supabase → tăng `attempts` → DONE khi thành công. Khởi động lại server ⇒ vẫn xử lý tiếp (dữ liệu ở DB). **Không** xoá hàng `app_sessions` đã thu hồi khi job còn PENDING.

### 5.6 Test (viết TRƯỚC) với đồng hồ giả
Biên `idle−1ms / idle / idle+1ms` và `absolute−1ms / absolute / absolute+1ms`; 2 activity đồng thời (barrier); logout CURRENT/ALL; Supabase lỗi (giả lỗi bằng cách trỏ URL Auth tới cổng chết cho riêng test) ⇒ PENDING, rồi phục hồi ⇒ DONE; khởi động lại module worker ⇒ job tiếp tục.
**Thử phá:** đổi `now >= oldIdle` thành `now > oldIdle` ⇒ ca biên `idle` phải đỏ.
