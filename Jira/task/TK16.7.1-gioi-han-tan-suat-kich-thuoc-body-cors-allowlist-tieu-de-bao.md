**Việc cần làm:** `apps/server/src/security/` (không dùng Redis — bộ đếm trong bộ nhớ tiến trình)
1. Bảng giới hạn (gom về một chỗ cấu hình, rà lại các chỗ đã làm ở Epic trước):
   | Hành động | Giới hạn | Khoá |
   |---|---|---|
   | Đăng nhập | 5 lần/phút | IP + username chuẩn hoá |
   | Chat | 5 tin/10 giây, **chung cả 2 kênh** | user |
   | Đề nghị hoà/đi lại | 1/10 giây | user |
   | Nhập mã phòng / join bằng mã | 10 lần/phút | user + IP |
   | Đăng ký, khôi phục | theo giới hạn Supabase Auth | — |
   Vượt ⇒ 429 `RATE_LIMITED` với thông báo rõ (không 500).
2. Bộ nhớ giới hạn có **dọn dẹp** (xoá khoá hết cửa sổ, chạy định kỳ; có số khoá tối đa) — không phình vô hạn.
3. Body tối đa **64 KB** (HTTP JSON + payload socket `maxHttpBufferSize`) ⇒ 413 / từ chối.
4. CORS và Socket.IO `cors.origin` = **đúng** danh sách `APP_ORIGIN` (không `*`).
5. Tiêu đề bảo mật (helmet): `Content-Security-Policy` nghiêm ngặt (default-src 'self'; connect-src API/WS/Supabase/LiveKit), `X-Frame-Options: DENY`/`frame-ancestors 'none'`, `X-Content-Type-Options: nosniff`, `Referrer-Policy: no-referrer`. Cấu hình tương tự cho web (Vercel headers ở TK16.8.2).
6. Xác thực bằng **Bearer token mỗi yêu cầu**, không dùng cookie liên miền.
7. Test `tests/integration/issue-134.test.ts` (đồng hồ giả cho cửa sổ tần suất).
