**Việc cần làm:** `apps/server/src/auth/login.controller.ts`, `login.service.ts`
1. `POST /api/v1/auth/login` (`@Public()`), body strict `{ username, password, rememberMe }`.
2. Luồng:
   ```
   ① username → chữ thường
   ② tra profiles → user_id (không có ⇒ lỗi chung)
   ③ Auth Admin API lấy email theo user_id (chỉ trong server)
   ④ TẠO CLIENT AUTH MỚI CHO MỖI YÊU CẦU: createClient(url, publishableKey, { auth: { persistSession: false, autoRefreshToken: false } })
   ⑤ signInWithPassword({ email, password })
   ⑥ bootstrap app_session: mode = rememberMe ? REMEMBERED : TEMPORARY; lấy sign_in_at qua private.get_auth_session_metadata;
      REMEMBERED: idle = sign_in_at + 30 ngày, absolute = NULL; TEMPORARY: idle = sign_in_at + 30 phút, absolute = sign_in_at + 12 giờ;
      INSERT ... ON CONFLICT (auth_session_id) DO NOTHING (replay không đổi mode/hạn)
   ⑦ trả { access_token, refresh_token, expires_in } — KHÔNG trả email
   ```
3. Mọi thất bại (không có username, sai mật khẩu) ⇒ **cùng** 401 `UNAUTHENTICATED` "Thông tin đăng nhập không đúng". Email chưa xác minh (Auth trả `email_not_confirmed`) ⇒ 403 `EMAIL_UNVERIFIED` (chỉ khi mật khẩu đúng — không dùng để dò tài khoản vì đã phải biết mật khẩu).
4. Giới hạn **5 lần/phút** theo `IP + username chuẩn hoá` (bộ nhớ trong tiến trình, có dọn khoá hết hạn; lần 6 ⇒ 429 `RATE_LIMITED`).
5. Không log body (chứa mật khẩu). Không có endpoint công khai nào tra username → email.
6. `POST /api/v1/auth/session/bootstrap` (dùng cho callback email/Google): lấy `auth_session_id` từ JWT đã verify, tạo app_session như bước ⑥ với mode do client chọn trước khi đăng nhập (mặc định REMEMBERED); bị trì hoãn tới đúng/sau hạn ban đầu ⇒ từ chối.
7. Test `tests/integration/issue-049.test.ts`.

**Bẫy dễ gặp:** dùng **một** client Auth dùng chung ⇒ yêu cầu của B nhận phiên của A.
