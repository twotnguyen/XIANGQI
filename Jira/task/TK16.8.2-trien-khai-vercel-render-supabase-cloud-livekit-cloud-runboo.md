**Việc cần làm:** (dùng tài khoản do trưởng nhóm cấp — **không tự mua dịch vụ trả phí**)
1. **Bản đồ triển khai**:
   | Thành phần | Nơi chạy |
   |---|---|
   | Web | Vercel (tĩnh; mọi đường dẫn rewrite về `index.html`) |
   | Server + realtime + AI child | **Một** Render Web Service (tiến trình sống lâu; AI child do backend spawn qua IPC, tối đa 2 worker) — hồ sơ **DEMO_SLEEP_ALLOWED** (được ngủ/khởi động lại; không dùng ping chống ngủ) |
   | DB + Auth | Supabase Cloud (áp migration bằng `supabase db push`; **không** `prisma migrate`) |
   | Media | LiveKit Cloud (không đặt chung với server) |
2. `render.yaml`, `vercel.json` (kèm headers bảo mật cho web), `.env.example` đầy đủ; giá trị thật điền trên dashboard, **không commit**; khoá bí mật **không** mang tiền tố `VITE_`.
3. Supabase Cloud: bật xác minh email, SMTP riêng (nếu có), redirect URLs = địa chỉ Vercel thật (`/auth/callback`); Google provider với redirect Supabase Cloud (bổ sung URI vào OAuth client ở TK06.4.1).
4. Server: `APP_ORIGIN` = đúng địa chỉ Vercel; `DATABASE_URL` dùng role `app_server`; health check Render trỏ `/healthz`.
5. Ghi `bootId` mỗi lần khởi động; kiểm khi dịch vụ ngủ/thức: ván cũ INTERRUPTED; UI có thông báo kết nối lại.
6. `docs/runbook.md`: xem log (Render/Vercel/Supabase), khởi động lại, quay về bản trước (Render rollback deploy, Vercel promote bản cũ), chạy migration, xoay khoá, và 5 sự cố thường gặp (CORS sai origin, redirect OAuth sai, LiveKit token lỗi, AI child không READY, DB hết kết nối) với cách xử lý.
7. Thiếu tài khoản dịch vụ nào ⇒ ghi rõ trong Task, nhãn `blocked-external`, làm phần còn lại.
