**Mục tiêu:** Server **dừng ngay với lỗi rõ ràng** khi thiếu/sai cấu hình, và **không bao giờ in giá trị bí mật**.

**Việc cần làm:**
1. `apps/server/src/config/env.ts`: schema Zod cho mọi biến server ở bảng TK01.2.2 (`DATABASE_URL` là URL `postgres(ql)://`, `PORT` số nguyên 1–65535 mặc định 3000, `APP_ORIGIN` URL, `INVITE_HMAC_KEY` chuỗi ≥ 32 ký tự, `AI_MAX_RUNNING` mặc định 2, `AI_MAX_QUEUED` mặc định 8; biến LiveKit tạm cho phép thiếu tới EP14 nhưng nếu có thì phải đủ bộ ba).
2. Hàm `loadEnv(source = process.env)` trả object đã kiểu hoá; sai thì ném lỗi liệt kê **tên** biến và lý do (ví dụ `DATABASE_URL: bắt buộc`), **không** kèm giá trị.
3. Gọi `loadEnv()` ở `main.ts` trước khi tạo app Nest; lỗi ⇒ `process.exit(1)` với thông báo tiếng Việt.
4. Cung cấp `ConfigModule` NestJS để service khác inject cấu hình (không đọc `process.env` rải rác).
5. Unit test `apps/server/src/config/env.test.ts`:
   - thiếu `DATABASE_URL` → lỗi chứa chữ `DATABASE_URL`;
   - `SUPABASE_SECRET_KEY=sk_test_BI_MAT_123` nhưng thiếu biến khác → thông báo lỗi **không chứa** chuỗi `sk_test_BI_MAT_123`;
   - đủ biến → trả đúng kiểu, `PORT` là number.

**File/module:** `apps/server/src/config/env.ts`, `config.module.ts`, `env.test.ts`, `apps/server/src/main.ts`.

**Bẫy dễ gặp:** `console.log(process.env)` hoặc in cả object lỗi Zod (Zod kèm `received` = giá trị) → rò bí mật. Chỉ in `path` + `message`.

**Bàn giao:** `ConfigService` dùng chung cho EP05 trở đi.

**Tự kiểm:** `DATABASE_URL= pnpm --filter @xiangqi/server start` thoát mã 1 với thông báo rõ; `pnpm test:unit` xanh.
