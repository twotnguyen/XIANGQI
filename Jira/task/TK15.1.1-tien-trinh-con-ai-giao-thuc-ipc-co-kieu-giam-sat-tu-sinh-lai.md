## 1. MỤC TIÊU (đọc trong 1 phút)

Chạy AI trong **tiến trình con riêng** (`apps/ai-worker`), nói chuyện với máy chủ qua **IPC có kiểu**. Mục đích: khi máy đang tính cấp Khó 3 giây, **máy chủ vẫn trả lời người khác < 500 ms** (Node một luồng — để chung là treo mọi ván — Luật tuyệt đối 4).

## 2. KHÁI NIỆM CẦN BIẾT

| Khái niệm | Giải thích |
|---|---|
| **Tiến trình con** | `child_process.fork()` — chương trình Node thứ hai, có luồng riêng; tính nặng không chặn máy chủ |
| **IPC** | Gửi tin qua lại giữa 2 tiến trình (`process.send` / `on('message')`) |
| **5 loại tin** | Server → AI: `SEARCH`, `CANCEL`. AI → Server: `RESULT`, `ERROR`, `READY` |
| **Map `jobId → resolver`** | Mỗi job chờ kết quả riêng — dùng biến đơn sẽ "nuốt" kết quả khi có nhiều job |
| **Tự sinh lại** | Tiến trình con chết ⇒ supervisor sinh lại; job đang chờ nhận lỗi; máy chủ **không** chết |

**Từ kỹ thuật cần tra:** [Zod](../05-TU-DIEN-KY-THUAT.md#zod) · [Test lanes](../05-TU-DIEN-KY-THUAT.md#test-lanes)

## 5. HƯỚNG DẪN LÀM TỪNG BƯỚC
1. **`protocol.ts`** — kiểu + schema Zod 5 loại tin:
   ```ts
   { type:'SEARCH', jobId, position, counts, maxDepth, budgetMs }   { type:'CANCEL', jobId }
   { type:'RESULT', jobId, result }  { type:'ERROR', jobId, message }  { type:'READY' }
   ```
   Tin sai kiểu ⇒ log + bỏ, **không** crash.
2. **`ai-worker/main.ts`**: nhận `SEARCH` ⇒ `searchBestMove` (`now = performance.now`) ⇒ `RESULT`; lỗi ⇒ `ERROR`, **không** thoát; khởi động xong ⇒ `READY`.
3. **Supervisor phía server**: `fork` khi server khởi động (**mặc định bật**, **không** có cờ tắt); map `jobId → resolver`; con chết ⇒ sinh lại + đếm + job chờ nhận lỗi; `SIGTERM`/`onModuleDestroy` ⇒ kill con + chờ thoát (không mồ côi).
4. **Test (viết TRƯỚC)**: 50 job ⇒ 50 kết quả; kill con ⇒ tự sinh lại; trong lúc AI tính HARD 3 s, gọi `GET /health` 20 lần ⇒ **p95 < 500 ms** (ghi số).
   **Thử phá:** chạy `searchBestMove` ngay trong tiến trình server ⇒ ca p95 phải đỏ.
