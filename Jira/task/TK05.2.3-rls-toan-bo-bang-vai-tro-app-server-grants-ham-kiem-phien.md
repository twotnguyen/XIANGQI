## 1. MỤC TIÊU (đọc trong 1 phút)

Khoá DB lại để **trình duyệt không bao giờ đọc/ghi thẳng** dữ liệu (luật `ARCH-02`):
1. Bật **RLS** cho **mọi** bảng ứng dụng, **không** policy cho `anon`/`authenticated`.
2. Tạo vai trò **`app_server`** (máy chủ dùng) — có quyền trên bảng nhưng **không** vượt RLS, **không** siêu quyền, **không** đọc bảng Auth.
3. 2 hàm kiểm phiên an toàn trong schema `private` cho máy chủ gọi.

## 2. KHÁI NIỆM CẦN BIẾT

| Khái niệm | Giải thích |
|---|---|
| **RLS** | Luật "ai đọc/ghi dòng nào" gắn trên bảng. Bật RLS mà **không** có policy ⇒ mặc định **cấm** — xem [Từ điển](../05-TU-DIEN-KY-THUAT.md#rls) |
| **`anon` / `authenticated`** | 2 vai trò Supabase dùng khi trình duyệt gọi thẳng REST (`/rest/v1/...`) bằng khoá publishable (và JWT nếu đã đăng nhập). Dự án **không** cho 2 vai trò này truy cập gì |
| **`app_server`** | Vai trò máy chủ NestJS dùng. `NOBYPASSRLS`, `NOSUPERUSER`; được quyền qua policy `FOR ALL TO app_server USING (true)` |
| **`SECURITY DEFINER` + `search_path = ''`** | Hàm chạy với quyền người tạo (để đọc `auth.sessions`) nhưng chỉ trả đúng thông tin cần, và không bị lừa gọi nhầm bảng |
| **Test bằng superuser** | Superuser bỏ qua mọi quyền ⇒ test "xanh" dù phân quyền sai. ⛔ Cấm |

**Từ kỹ thuật cần tra:** [RLS](../05-TU-DIEN-KY-THUAT.md#rls) · [Token](../05-TU-DIEN-KY-THUAT.md#jwt) · [SQL thuần/Prisma](../05-TU-DIEN-KY-THUAT.md#sql-prisma)

## 5. HƯỚNG DẪN LÀM TỪNG BƯỚC

1. `ALTER TABLE public.<bảng> ENABLE ROW LEVEL SECURITY;` cho **mọi** bảng: profiles, friendships, rooms, room_members, room_blocks, user_active_room, invitations, matches, match_moves, match_events, active_players, command_receipts, match_proposals, room_rematch_votes, room_command_receipts, room_side_swap_proposals, chat_contexts, chat_private_segments, chat_private_participants, chat_messages, media_policies, media_transports, media_jobs, ai_jobs, client_controls, app_sessions, auth_security_jobs.
2. `REVOKE ALL ON ALL TABLES IN SCHEMA public FROM anon, authenticated;` — **không** tạo policy nào cho 2 vai trò này.
3. Vai trò máy chủ:
   ```sql
   CREATE ROLE app_server LOGIN PASSWORD '<đặt qua biến khi seed local>' NOBYPASSRLS NOSUPERUSER;
   GRANT USAGE ON SCHEMA public TO app_server;
   GRANT SELECT, INSERT, UPDATE, DELETE ON ALL TABLES IN SCHEMA public TO app_server;
   GRANT USAGE, SELECT ON ALL SEQUENCES IN SCHEMA public TO app_server;
   -- mỗi bảng:
   CREATE POLICY app_server_all ON public.<bảng> FOR ALL TO app_server USING (true) WITH CHECK (true);
   ```
   ⛔ **Không** `BYPASSRLS`, **không** SUPERUSER, **không** cấp SELECT trên `auth.users`/`auth.sessions`.
4. Schema `private` (không phơi qua REST):
   - `private.is_auth_session_active(session_id uuid, user_id uuid) RETURNS boolean SECURITY DEFINER SET search_path = ''`.
   - `private.get_auth_session_metadata(session_id uuid, user_id uuid) RETURNS TABLE(created_at timestamptz) SECURITY DEFINER SET search_path = ''` — chỉ trả `created_at` khi cặp khớp **và** phiên còn hiệu lực; sai/hết hạn ⇒ rỗng; **không** trả email/token.
   - Viết tên bảng đầy đủ (`auth.sessions`), không SQL động; `REVOKE ALL ON FUNCTION … FROM PUBLIC, anon, authenticated`; `GRANT EXECUTE … TO app_server`; `GRANT USAGE ON SCHEMA private TO app_server`.
5. `.env.example`: `DATABASE_URL` của máy chủ dùng user `app_server`; thêm `DATABASE_ADMIN_URL` (chỉ cho seed/test).
6. Test (viết TRƯỚC) `issue-043.test.ts`: kết nối bằng **từng vai trò thật** — `anon`/`authenticated` qua REST (khoá publishable + JWT), `app_server` qua `pg`.

**Thử phá:** tạo tạm policy `FOR SELECT TO anon USING (true)` trên `profiles` ⇒ test anon phải đỏ.
