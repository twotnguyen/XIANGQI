**Việc cần làm:**
1. `<ts>_media.sql`
   - **`media_policies`**: PK `(match_id, user_id)`, `camera_desired`, `microphone_desired`, `camera_applied`, `microphone_applied` (mỗi cột CHECK IN ('OFF','OPPONENT_ONLY','OPPONENT_AND_SPECTATORS'), mặc định `OFF`), `policy_version int DEFAULT 0`, `applied_version int DEFAULT 0`, `status` CHECK IN ('APPLYING','APPLIED','FAILED') DEFAULT 'APPLIED'.
   - **`media_transports`** — **một hàng mỗi thế hệ, không ghi đè**: `id`, `match_id`, `kind` (CAMERA/MICROPHONE), `audience` (PRIVATE/WATCH), `generation int`, `room_name text` (chứa nonce 128-bit, không tái dùng), `state` (READY/ROTATING/RETIRED); `UNIQUE(room_name)`, `UNIQUE(match_id, kind, audience, generation)`.
   - **`media_jobs`**: `id`, `match_id`, `status` (PENDING/RUNNING/DONE/FAILED), `attempts CHECK >= 0`, `operation_id UNIQUE`, `source_kind`, `old_transport_ids uuid[]`, `target_epoch`, `started_at`, `deadline_at CHECK >= started_at`, `lease_until`, `last_error`, `confirmed_at`, `created_at`; index `(status, lease_until)` để lấy lại job RUNNING bị kẹt sau khi máy chủ khởi động lại.
2. `<ts>_ai_controls.sql`
   - **`ai_jobs`**: `match_id PK` (một hàng mỗi ván), `job_id uuid NULL`, `job_version int CHECK >= 0` (tăng xuyên suốt ván), `expected_version int NULL`, `status` CHECK IN ('IDLE','QUEUED','THINKING','FAILED'), `attempts CHECK BETWEEN 0 AND 2`, `queued_at`, `started_at`, `completed_at`, `deadline_at`; index `(status, queued_at)`. Trạng thái job **không** tăng `matches.version`.
   - **`client_controls`**: PK `(user_id, kind)` — mỗi nguồn (CAMERA/MICROPHONE) của một user chỉ một tab giữ; `owner_client_id uuid NULL`, `app_session_id uuid NULL FK app_sessions`, `ownership_epoch bigint CHECK >= 0`, `match_id NULL FK`, `operation_id uuid UNIQUE NULL`, `target_client_id uuid NULL`, `operation_state` CHECK IN ('IDLE','STOPPING','APPLIED','ERROR','CANCELLED') DEFAULT 'IDLE', `started_at`, `deadline_at` (CHECK ≥ started_at), `updated_at`, `old_transport_refs jsonb`, `last_error`; CHECK `operation_state <> 'STOPPING' OR (operation_id IS NOT NULL AND target_client_id IS NOT NULL AND started_at IS NOT NULL AND deadline_at IS NOT NULL)`. ⚠ Không dùng bảng này để khoá đi cờ/chat (mọi tab đều thao tác được).
   - **`app_sessions`**: `id uuid PK`, `user_id FK`, `auth_session_id uuid UNIQUE`, `mode` CHECK IN ('REMEMBERED','TEMPORARY'), `created_at`, `last_active_at`, `idle_expires_at` (CHECK ≥ created_at), `absolute_expires_at NULL`, `revoked_at NULL`; CHECK `(mode='TEMPORARY' AND absolute_expires_at IS NOT NULL) OR (mode='REMEMBERED' AND absolute_expires_at IS NULL)`; index `(user_id, revoked_at)`, `(idle_expires_at)`.
   - **`auth_security_jobs`**: `id`, `user_id FK`, `operation_id UNIQUE`, `reason` CHECK IN ('PASSWORD_CHANGED','LOGOUT'), `scope` CHECK IN ('CURRENT','ALL'), `target_auth_session_ids uuid[] NOT NULL`, `revocation_cutoff timestamptz NOT NULL`, `status` (PENDING/RUNNING/DONE/FAILED), `created_at`, `lease_until`, `attempts CHECK >= 0`, `last_error`; CHECK `scope <> 'CURRENT' OR cardinality(target_auth_session_ids) = 1`; CHECK `reason <> 'PASSWORD_CHANGED' OR scope = 'ALL'`; trigger chặn UPDATE các cột payload (user_id, reason, scope, target, cutoff) sau insert. **Không** lưu mật khẩu/hash/token.
   - Trigger trên `auth.users` khi `encrypted_password` thay đổi: trong **cùng transaction** đặt `revoked_at` (fence) cho mọi `app_sessions` của user và ghi `auth_security_jobs` (reason PASSWORD_CHANGED, scope ALL). Trigger không gọi mạng.
3. Test `tests/integration/issue-041.test.ts`, `issue-042.test.ts`.

**Bẫy dễ gặp:** ghi đè `room_name` thế hệ cũ rồi mới xoá phòng LiveKit ⇒ máy chủ chết giữa chừng thì mất địa chỉ cần thu hồi ⇒ người xem cũ vẫn nhận media.
