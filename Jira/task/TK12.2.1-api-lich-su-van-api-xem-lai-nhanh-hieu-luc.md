## 1. MỤC TIÊU (đọc trong 1 phút)

Viết 3 API **chỉ đọc**:

| API | Ai gọi được | Trả gì |
|---|---|---|
| `GET /api/v1/history?cursor=` | Người đã đăng nhập | Danh sách **ván của chính mình**, 20 ván/trang, mới nhất trước |
| `GET /api/v1/history/:matchId/replay` | **Chỉ** người chơi của ván đó | Dữ liệu xem lại ván |
| `GET /api/v1/rooms/:roomId/replay/:matchId` | Thành viên **hiện tại** của phòng, chỉ cho **ván hiện tại** của phòng khi phòng đã xong ván | Dữ liệu xem lại ván |

## 2. KHÁI NIỆM CẦN BIẾT

**Từ kỹ thuật cần tra trước khi làm:** [Phân trang con trỏ](../05-TU-DIEN-KY-THUAT.md#cursor) · [IDOR](../05-TU-DIEN-KY-THUAT.md#idor) · [Index & EXPLAIN](../05-TU-DIEN-KY-THUAT.md#index) · [N+1](../05-TU-DIEN-KY-THUAT.md#n-plus-1) · [CTE đệ quy](../05-TU-DIEN-KY-THUAT.md#cte) · [SQL thuần/Prisma](../05-TU-DIEN-KY-THUAT.md#sql-prisma) · [Migration](../05-TU-DIEN-KY-THUAT.md#migration) · [ApiResult](../05-TU-DIEN-KY-THUAT.md#api-result) · [Thử phá](../05-TU-DIEN-KY-THUAT.md#mutation)

| Khái niệm | Giải thích |
|---|---|
| **Phân trang bằng con trỏ (cursor)** | Không dùng `OFFSET 20` (chậm và dễ trùng/sót khi có ván mới chen vào). Con trỏ = giá trị `(ended_at, id)` của dòng cuối trang trước; trang sau lấy các dòng **nhỏ hơn** con trỏ. `id` dùng để phá hoà khi hai ván kết thúc cùng mili-giây |
| **IDOR** | Lỗi bảo mật "đoán mã": người ngoài đổi `matchId` trên URL thành mã ván của người khác. Chặn bằng cách **luôn** kiểm người gọi có phải người chơi của ván đó, dù mã ván đúng |
| **Nhánh hiệu lực** | Chuỗi nước từ gốc tới `head_move_id` (xem TK12.1.2). Hàm `getActiveBranch()` đã có ở TK10.3.1 |
| **`EXPLAIN`** | Lệnh PostgreSQL cho biết truy vấn sẽ chạy thế nào. Thấy `Index Scan` là dùng index (nhanh); `Seq Scan` trên bảng lớn là quét toàn bộ (chậm) |

## 5. HƯỚNG DẪN LÀM TỪNG BƯỚC

### 5.1 Migration index (file `.sql` qua Supabase CLI — ⛔ không `prisma migrate`)

```sql
-- supabase/migrations/<timestamp>_history_indexes.sql
-- 🟡 tên index là đề xuất
CREATE INDEX IF NOT EXISTS matches_red_history_idx   ON matches (red_user_id,   ended_at DESC, id DESC) WHERE status IN ('FINISHED','INTERRUPTED');
CREATE INDEX IF NOT EXISTS matches_black_history_idx ON matches (black_user_id, ended_at DESC, id DESC) WHERE status IN ('FINISHED','INTERRUPTED');
```
Sau đó `pnpm db:reset` và chạy lại `prisma db pull` nếu kiểu dữ liệu đổi.

### 5.2 `GET /api/v1/history?cursor=<chuỗi>`

1. Lấy `me = req.user.id`. **Không** nhận `userId` từ query.
2. Điều kiện: `status IN ('FINISHED','INTERRUPTED') AND (red_user_id = me OR black_user_id = me)`. Ván với máy có một trong hai cột là `me`, cột kia `NULL` ⇒ vẫn ra.
3. Sắp xếp `ended_at DESC, id DESC`, lấy **21** dòng (dòng thứ 21 chỉ để biết còn trang sau).
4. 🟡 Con trỏ: base64 của `{"endedAt":"<ISO>","id":"<uuid>"}`; trang sau thêm điều kiện `(ended_at, id) < (cursor.endedAt, cursor.id)`. Con trỏ sai định dạng ⇒ `VALIDATION_ERROR`.
5. Trả (🟡 tên trường — đặc tả chỉ quy định **nội dung** mỗi dòng: đối thủ, bên, kết quả, nguyên nhân, thời điểm, có đi lại):
   ```jsonc
   {
     "items": [{
       "matchId": "uuid",
       "opponent": { "displayName": "Bình" },     // hoặc { "ai": "HARD" } khi chơi với máy
       "mySide": "RED",
       "result": "WIN",                            // WIN | LOSS | DRAW | INTERRUPTED
       "reason": "CHECKMATE",                      // 1 trong 11 giá trị OutcomeReason
       "endedAt": "2026-10-19T08:30:00.000Z",
       "moveCount": 42,                            // số nước trên NHÁNH HIỆU LỰC
       "hadUndo": true                             // có ít nhất 1 sự kiện UNDO
     }],
     "nextCursor": "eyJlbmRlZEF0Ijo…" | null
   }
   ```
6. Tính `result`: `status='INTERRUPTED'` ⇒ `INTERRUPTED`; `outcome_winner IS NULL` ⇒ `DRAW`; `outcome_winner = mySide` ⇒ `WIN`; còn lại `LOSS`.
7. **Không** trả email, không trả `userId` của đối thủ (chỉ `displayName`).
8. Tránh truy vấn N+1: lấy `moveCount`, `hadUndo` bằng một truy vấn gộp (`GROUP BY match_id`) cho cả 20 ván, không lặp từng ván.

### 5.3 `GET /api/v1/history/:matchId/replay`

1. Tìm ván theo `matchId`. **Không tồn tại** hoặc **người gọi không phải `red_user_id`/`black_user_id`** ⇒ **cùng** `FORBIDDEN` (không phân biệt "không có" với "không được xem", để người ngoài không dò ra mã nào tồn tại).
2. Ván đang `ACTIVE` ⇒ `FORBIDDEN` (lịch sử chỉ có ván đã kết thúc; ván đang chơi xem ở phòng).
3. Trả (🟡 tên trường — đặc tả quy định nội dung: thế ban đầu, nước nhánh hiệu lực, số lần đi lại, kết quả):
   ```jsonc
   {
     "matchId": "uuid",
     "initialPosition": { /* Position thế ban đầu */ },
     "moves": [ { "from": {"x":1,"y":7}, "to": {"x":4,"y":7}, "side": "RED" }, … ], // CHỈ nhánh hiệu lực, đúng thứ tự
     "undoCount": 2,
     "hadUndo": true,
     "outcome": { "status": "FINISHED", "reason": "RESIGN", "winnerSide": "BLACK" },
     "red":   { "displayName": "An" }   | { "ai": "EASY" },
     "black": { "displayName": "Bình" } | { "ai": "EASY" }
   }
   ```
   Không trả id của nước bị bỏ, không trả chat.

### 5.4 `GET /api/v1/rooms/:roomId/replay/:matchId`

Kiểm **mỗi lần gọi** (không cache quyền):
1. Người gọi là thành viên **hiện hành** của phòng (`room_members` còn hiệu lực, chưa rời, chưa bị đuổi).
2. Phòng `status = 'FINISHED'` và `rooms.current_match_id = :matchId`.
3. Sai bất kỳ điều nào ⇒ `FORBIDDEN`.
Trả cùng định dạng 5.3.

> Người chơi của ván cũ hơn trong phòng vẫn xem được qua `/history/:matchId/replay` (quyền người chơi). Người **xem** thì chỉ ván hiện tại (`BR-HIS-14`).
