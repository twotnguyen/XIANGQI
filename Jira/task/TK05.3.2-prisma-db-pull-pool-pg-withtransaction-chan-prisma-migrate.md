**Việc cần làm:**
1. `apps/server/prisma/schema.prisma`: chỉ `generator client` + `datasource db` (`url = env("DATABASE_URL")`), bật `previewFeatures = ["multiSchema"]`, `schemas = ["auth","public"]`. Chạy `prisma db pull` để **hút** model — không viết model tay. `prisma generate`.
2. Script `package.json` của server: `"prisma:pull": "prisma db pull && prisma generate"`, `"prisma:migrate": "echo 'CẤM. Schema do Supabase CLI quản lý (TECH-10).' && exit 1"`. Thêm script gốc tương ứng.
3. `apps/server/src/db/prisma.ts` — `PrismaService` (NestJS provider) dùng cho **đọc/ghi đơn giản**: hồ sơ, bạn bè, lời mời, lịch sử tin nhắn (đọc), lịch sử ván, sảnh.
4. `apps/server/src/db/pool.ts` — pool `pg` bằng role `app_server` cho **SQL thuần**.
5. `apps/server/src/db/transaction.ts`:
   ```ts
   withTransaction<T>(fn: (client: PoolClient) => Promise<T>, opts?: { isolation?: 'READ COMMITTED' | 'SERIALIZABLE' }): Promise<T>
   // BEGIN → fn → COMMIT; lỗi → ROLLBACK rồi ném lại; luôn release client
   ```
6. `docs/DB-BOUNDARY.md` — bảng ranh giới:
   | Dùng Prisma | Dùng SQL thuần (`withTransaction` + `FOR UPDATE`) |
   |---|---|
   | Hồ sơ, tên hiển thị | Đi một nước cờ |
   | Bạn bè, lời mời kết bạn | Đầu hàng, xin hoà, xin đi lại |
   | Lời mời phòng, mã, link (phát hành) | Nhận người vào phòng (đếm sức chứa) |
   | Lịch sử tin nhắn (đọc, có điều kiện quyền đủ) | Bắt đầu ván (hai người sẵn sàng) |
   | Lịch sử ván (đọc) | Gửi chat (kiểm quyền rồi ghi) |
   | Danh sách sảnh | Tái đấu (đổi bên); mọi bộ đếm thời hạn; đuổi người xem; thu hồi quyền |
   Quy tắc: cần **khoá dòng**, **thứ tự khoá**, hoặc **đếm rồi ghi trong cùng transaction** ⇒ SQL thuần. Thứ tự khoá: **phòng → người → ván**. Không giữ khoá khi gọi ra ngoài (AI, LiveKit).
7. Test tích hợp `tests/integration/issue-045.test.ts`.

**Bẫy dễ gặp:** chạy `prisma migrate` một lần là mất RLS, CHECK, unique hoãn kiểm.
