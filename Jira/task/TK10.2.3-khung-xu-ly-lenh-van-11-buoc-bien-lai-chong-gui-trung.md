## 1. MỤC TIÊU (đọc trong 1 phút)

Viết **một** khung xử lý lệnh ván dùng chung — `CommandPipeline` — chạy đúng **11 bước** (EP10 §5) cho **mọi** lệnh: đi nước, đầu hàng, đề nghị, đi lại… Đảm bảo:
1. Hai lệnh cùng ván chạy **lần lượt** (không tranh nhau).
2. Gửi lại cùng lệnh 3 lần ⇒ **đúng 1** kết quả (biên lai).
3. Lỗi giữa chừng ⇒ **không** thay đổi gì. **Không** giữ khoá khi gọi ra ngoài.

## 2. KHÁI NIỆM CẦN BIẾT

| Khái niệm | Giải thích |
|---|---|
| **Pipeline + handler** | Pipeline lo phần chung (khoá, biên lai, version, đồng hồ, commit, phát tin). Mỗi lệnh chỉ viết **handler** (bước ⑧–⑨) |
| **Biên lai (`command_receipts`)** | Khoá `(match_id, actor_id, command_id)`. Gửi lại cùng lệnh ⇒ trả kết quả cũ, không làm lại |
| **`payloadHash`** | `SHA256(canonicalJSON({ type, expectedVersion, payload }))` — JSON **sắp xếp khoá** để `{a,b}` và `{b,a}` ra cùng hash |
| **Trả trạng thái HIỆN TẠI khi gửi lại** | Trả `appliedVersion` gốc + snapshot **đọc lại từ DB** (đồng hồ mới). Trả số dư đồng hồ đã lưu ⇒ người chơi được "hoàn giờ" mỗi lần mạng chập chờn |
| **Bước ⑦ trước ⑧** | Tính lại đồng hồ **trước** khi kiểm luật: hết giờ ⇒ kết thúc TIMEOUT và **từ chối** lệnh |
| **`afterCommit`** | Chỗ gửi job AI/media **sau** COMMIT — không giữ khoá khi gọi ra ngoài (`ARCH-07`) |

**Từ kỹ thuật cần tra:** [Transaction](../05-TU-DIEN-KY-THUAT.md#transaction) · [Khoá dòng](../05-TU-DIEN-KY-THUAT.md#khoa-dong) · [Thứ tự khoá & deadlock](../05-TU-DIEN-KY-THUAT.md#deadlock) · [Idempotency](../05-TU-DIEN-KY-THUAT.md#idempotency) · [Version](../05-TU-DIEN-KY-THUAT.md#version) · [Pipeline 11 bước](../05-TU-DIEN-KY-THUAT.md#pipeline) · [Race](../05-TU-DIEN-KY-THUAT.md#race) · [Barrier](../05-TU-DIEN-KY-THUAT.md#barrier)

## 5. HƯỚNG DẪN LÀM TỪNG BƯỚC

### 5.1 Chữ ký
```ts
CommandPipeline.execute(actor, matchId, { commandId, commandType, expectedVersion, payload }, handler)
```

### 5.2 Mười một bước (chép từ EP10)
```
① xác thực (JWT + phiên)
② đọc match.room_id (bất biến) để biết khoá phòng nào
③ BEGIN
④ ONLINE: SELECT rooms … FOR UPDATE → SELECT matches … FOR UPDATE   ·  AI: chỉ SELECT matches … FOR UPDATE
⑤ tra command_receipts: có + cùng hash ⇒ trả appliedVersion gốc + trạng thái HIỆN TẠI; khác hash ⇒ COMMAND_ID_REUSED
⑥ ván ACTIVE + expectedVersion == version (sai ⇒ VERSION_CONFLICT)
⑦ clock.recompute() — hết giờ ⇒ finalizer TIMEOUT, TỪ CHỐI lệnh      (tạm no-op, TODO TK11.1.1)
⑧ handler: kiểm lượt · vai trò · luật
⑨ handler: áp dụng · version++ · ghi sự kiện
⑩ ghi biên lai (CHỈ khi thành công)
⑪ COMMIT → afterCommit (phát tin, job AI/media). Lỗi phát tin KHÔNG huỷ dữ liệu
```

### 5.3 Biên lai
| Trường hợp | Xử lý |
|---|---|
| Chưa có | xử lý + ghi |
| Có, **cùng** hash | trả `appliedVersion` gốc + snapshot đọc lại |
| Có, **khác** hash | `409 COMMAND_ID_REUSED` |
| Khác ván / khác người gửi | xử lý bình thường |
Lệnh bị từ chối (sai luật / lượt / version) ⇒ **không** ghi biên lai.

### 5.4 Test (viết TRƯỚC)
- `issue-085`: 2 lệnh song song cùng ván (barrier, 2 kết nối) ⇒ tuần tự; transaction tay khoá **ván trước rồi phòng** chạy song song ⇒ pipeline **không** khoá ngược (ghi log thứ tự khoá); ném lỗi sau ⑨ ⇒ rollback; broadcaster ném lỗi sau commit ⇒ dữ liệu còn; spy: 0 lời gọi HTTP ra ngoài giữa BEGIN và COMMIT.
- `issue-086`: gửi 3 lần cùng lệnh; cùng id khác payload; hash `RESIGN {}` ≠ `UNDO_AI {}`; đảo thứ tự khoá object ⇒ cùng hash.
**Thử phá:** (1) ghi biên lai trước bước ⑧ ⇒ ca "sai lượt không có biên lai" phải đỏ; (2) đổi thứ tự khoá thành ván → phòng ⇒ ca deadlock phải đỏ.
