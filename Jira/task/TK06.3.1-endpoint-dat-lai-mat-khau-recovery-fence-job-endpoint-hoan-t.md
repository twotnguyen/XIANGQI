## 1. MỤC TIÊU (đọc trong 1 phút)

Hai API phía máy chủ:
1. `POST /api/v1/auth/reset-password` — đặt mật khẩu mới từ link "Quên mật khẩu". Xong ⇒ **mọi phiên cũ bị đăng xuất** (kẻ gian đang dùng tài khoản bị đá ra).

## 5. HƯỚNG DẪN LÀM TỪNG BƯỚC

### 5.1 `POST /api/v1/auth/reset-password` body strict `{ newPassword, operationId }`
```
⓪ Chỉ nhận recovery session; phiên thường ⇒ 403 FORBIDDEN. Mật khẩu 10–128 ⇒ ngoài ⇒ 400
① Transaction: revoked_at cho MỌI app_sessions của user
   + INSERT auth_security_jobs (PASSWORD_CHANGED, ALL, snapshot, operation_id)
   (operationId đã có ⇒ trả trạng thái cũ, không tạo job mới)
② Ngoài transaction: Supabase Admin updateUserById(userId, { password })
③ Thành công ⇒ { status: 'COMPLETED' } · lỗi ⇒ giữ fence, { status: 'PENDING' }
```
Không log/lưu mật khẩu. Guard (TK06.1.1) phải **từ chối** recovery session ở mọi route sản phẩm.

### 5.2 `POST /api/v1/auth/complete-profile` body strict `{ username, displayName? }`
```sql
BEGIN;
SELECT username FROM profiles WHERE user_id = $1 FOR UPDATE;
-- đã có username ⇒ ROLLBACK, 409 CONFLICT "Tên đăng nhập đã được chọn, không thể đổi"
UPDATE profiles SET username = lower($2), display_name = coalesce($3, lower($2)), profile_verified_at = now()
 WHERE user_id = $1;
-- 23505 ⇒ 409 CONFLICT "Tên đăng nhập đã được sử dụng"
COMMIT;
```
Sai định dạng ⇒ `400 VALIDATION_ERROR`. Route này **được phép** khi username NULL (ngoại lệ của onboarding guard).

### 5.3 Test (viết TRƯỚC)
- `issue-052`: 2 phiên → reset → cả 2 token 401; gọi thẳng Supabase `updateUser` ⇒ vẫn fence + có job; phiên thường gọi reset ⇒ 403; Supabase lỗi ⇒ PENDING rồi retry cùng `operationId` ⇒ COMPLETED, 1 job.
- `issue-054`: 2 user cùng chọn `erin` (barrier, 2 kết nối) ⇒ đúng 1 thành công; cùng user gọi 2 lần song song ⇒ 1 thành công, 1 409.
**Thử phá:** bỏ `FOR UPDATE` ⇒ ca "cùng user 2 lần song song" phải đỏ (chạy lặp 20 lần).
