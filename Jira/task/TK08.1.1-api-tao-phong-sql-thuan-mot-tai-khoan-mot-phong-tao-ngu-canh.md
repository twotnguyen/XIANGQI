**Việc cần làm:** `apps/server/src/modules/rooms/rooms.controller.ts`, `rooms.service.ts`
1. `POST /api/v1/rooms` body `CreateRoomSchema` (`{ name 1..60, visibility, timeControl ∈ {0,300,600,900} }`, `.strict()`).
2. **Một transaction SQL thuần**:
   ```
   ① SELECT ... FROM profiles WHERE user_id=$actor FOR UPDATE      (khoá người để tuần tự hoá 2 yêu cầu của cùng người)
   ② có hàng user_active_room?  → ALREADY_IN_ROOM (409)
   ③ có active_players cho ván AI đang ACTIVE? → CONFLICT (409)
   ④ INSERT rooms (status WAITING, room_version 0, config_revision 0, watch_epoch 0)
   ⑤ INSERT room_members (role PLAYER, side RED, membership_id mới, ready false)
   ⑥ INSERT user_active_room
   ⑦ INSERT chat_contexts (generation 0) + UPDATE rooms.current_chat_context_id
      + INSERT chat_private_segments (segment solo của chủ phòng) + chat_private_participants (user, membership_id)
   ⑧ COMMIT
   ```
   Lỗi ở bất kỳ bước ⇒ rollback toàn bộ (không để phòng/thành viên/con trỏ/chat mồ côi). PK `user_active_room` là chốt chặn cuối (23505 ⇒ 409 `ALREADY_IN_ROOM`).
3. Trả `{ room: RoomView }` (không chứa mã/token). `RoomView` dùng chung cho các API phòng sau: `{ id, name, ownerId, visibility, status, roomVersion, configRevision, timeControl, members[], spectatorCount, currentMatchId, currentChatContextId }`.
4. Sau commit: nếu PUBLIC gọi `lobbyPublisher.roomChanged(roomId)` (hàm tạm lưu vào hàng đợi trong bộ nhớ; TK08.2.1 nối vào socket). Rollback thì không phát.
5. Test `tests/integration/issue-061.test.ts` (đồng thời bằng `withBarrier(2)` với 2 kết nối).

**Bẫy dễ gặp:** kiểm "đang ở phòng khác" **ngoài** transaction ⇒ 2 yêu cầu song song cùng tạo được phòng.
