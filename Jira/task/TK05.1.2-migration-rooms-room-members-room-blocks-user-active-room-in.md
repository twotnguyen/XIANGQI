**Việc cần làm:** `supabase/migrations/<ts>_rooms.sql`
1. **`rooms`**: `id uuid PK`, `name`, `owner_id FK profiles`, `visibility`, `status`, `room_version bigint`, `config_revision bigint NOT NULL DEFAULT 0`, `time_control int`, `current_match_id uuid NULL` (FK thêm ở TK05.1.3), `current_chat_context_id uuid NULL` (FK thêm ở TK05.2.1), `watch_epoch bigint NOT NULL DEFAULT 0`, `finished_at timestamptz NULL`, `created_at`.
   ```sql
   CHECK (char_length(name) BETWEEN 1 AND 60)
   CHECK (visibility IN ('PUBLIC','CODE_ONLY','LOCKED'))
   CHECK (status IN ('WAITING','PLAYING','FINISHED','CLOSED'))
   CHECK (time_control IN (0,300,600,900))
   CHECK (room_version >= 0 AND config_revision >= 0 AND watch_epoch >= 0)
   ```
   Index sảnh: `(created_at DESC, id DESC) WHERE visibility='PUBLIC' AND status IN ('WAITING','PLAYING')` (**không** gồm FINISHED).
2. **`room_members`**: `room_id`, `user_id`, `membership_id uuid NOT NULL UNIQUE` (mỗi lần nhận ghế một id mới, không tái dùng), `role`, `side`, `ready boolean NOT NULL DEFAULT false`, `ready_revision bigint NOT NULL DEFAULT 0 CHECK >= 0`, `ready_config_revision bigint NULL`, `joined_at`.
   ```sql
   PRIMARY KEY (room_id, user_id)
   CHECK (role IN ('PLAYER','SPECTATOR'))
   CHECK ((role='PLAYER' AND side IS NOT NULL AND side IN ('RED','BLACK')) OR (role='SPECTATOR' AND side IS NULL))
   CHECK ((ready AND ready_config_revision IS NOT NULL) OR (NOT ready AND ready_config_revision IS NULL))
   CHECK (role='PLAYER' OR NOT ready)
   ```
   `ALTER TABLE ... ADD CONSTRAINT room_members_side_uniq UNIQUE (room_id, side) DEFERRABLE INITIALLY DEFERRED;` — để **đổi bên khi tái đấu/đổi bên** trong cùng transaction.
   ⚠ Viết `side IS NOT NULL` tường minh: `side IN (...)` với NULL cho kết quả UNKNOWN và CHECK sẽ **cho lọt**.
3. **`room_blocks`**: `room_id`, `user_id`, `blocked_by`, `blocked_at`; `PRIMARY KEY (room_id, user_id)`.
4. **`user_active_room`**: `user_id PK`, `room_id` — ép **một tài khoản một phòng**.
5. **`invitations`** (storage, logic phát hành ở EP08):
   | Cột | Ràng buộc |
   |---|---|
   | `id` | uuid PK |
   | `room_id` | NOT NULL FK rooms |
   | `issuer_id` | NOT NULL FK profiles |
   | `recipient_id` | FK profiles; **DIRECT bắt buộc, CODE/LINK phải NULL** |
   | `kind` | CHECK IN ('CODE','LINK','DIRECT') |
   | `grant_role` | CHECK IN ('PLAY','WATCH') |
   | `secret_hash` | DIRECT phải NULL; CODE/LINK NOT NULL; UNIQUE khi khác NULL; **không có cột mã/token gốc** |
   | `status` | NOT NULL CHECK IN ('PENDING','CONSUMED','REJECTED','REVOKED','EXPIRED') |
   | `watch_epoch` | WATCH bắt buộc ≥ 0; PLAY phải NULL |
   | `created_at`, `expires_at` | NOT NULL, `CHECK (expires_at > created_at)` |
   | `consumed_at` | nullable |
   Index `(recipient_id, status, expires_at)` (hộp thư); `(room_id, grant_role, watch_epoch, status)` (thu hồi); partial UNIQUE `(issuer_id, recipient_id, room_id, grant_role) WHERE kind='DIRECT' AND status='PENDING'`. FK dùng RESTRICT.
6. Comment đầu file: *"Thứ tự khoá dòng: rooms → profiles → matches. Sức chứa (2 người chơi + 5 người xem) KHÔNG kiểm bằng CHECK mà kiểm trong transaction có khoá phòng (EP08)."*
7. Test `tests/integration/issue-037.test.ts` — đủ các ca ở TK05.1.2.

**Bẫy dễ gặp:** `UNIQUE (room_id, side)` không DEFERRABLE ⇒ tái đấu đổi bên luôn lỗi giữa chừng.
