## 1. MỤC TIÊU (đọc trong 1 phút)

Tạo 5 bảng cho **phòng chơi**: `rooms`, `room_members`, `room_blocks`, `user_active_room`, `invitations`. Ràng buộc DB đảm bảo:
- Mỗi phòng tối đa 1 người cầm ĐỎ, 1 người cầm ĐEN — **nhưng** vẫn đổi bên được trong 1 transaction (tái đấu).
- Một tài khoản chỉ ở **một** phòng.
- Lời mời **không** lưu mã/link gốc — chỉ lưu **hash**.

## 2. KHÁI NIỆM CẦN BIẾT

| Khái niệm | Giải thích |
|---|---|
| **Unique hoãn kiểm** | `UNIQUE (room_id, side) DEFERRABLE INITIALLY DEFERRED` — chỉ kiểm lúc COMMIT ⇒ đổi A↔B giữa chừng không lỗi. Xem [Từ điển](../05-TU-DIEN-KY-THUAT.md#unique-hoan-kiem) |
| **`membership_id`** | Mỗi lần nhận ghế một id **mới** — để lệnh cũ của phiên ngồi trước không áp nhầm cho lần ngồi sau |
| **Hash mã mời** | Chỉ lưu `secret_hash` (HMAC của mã/token). Lộ DB cũng không lấy được mã để vào phòng |
| **Partial index** | Index chỉ gồm các dòng thoả điều kiện (ví dụ phòng PUBLIC đang WAITING/PLAYING) — nhỏ và nhanh cho sảnh |
| **NULL trong CHECK** | `side IN ('RED','BLACK')` với `side = NULL` cho kết quả **UNKNOWN** ⇒ CHECK **cho lọt**. Phải viết `side IS NOT NULL AND …` |

**Từ kỹ thuật cần tra:** [Unique hoãn kiểm](../05-TU-DIEN-KY-THUAT.md#unique-hoan-kiem) · [Ràng buộc](../05-TU-DIEN-KY-THUAT.md#rang-buoc) · [Index & EXPLAIN](../05-TU-DIEN-KY-THUAT.md#index) · [Thứ tự khoá](../05-TU-DIEN-KY-THUAT.md#deadlock)

## 5. HƯỚNG DẪN LÀM TỪNG BƯỚC

### 5.1 `rooms`
Cột: `id uuid PK`, `name`, `owner_id FK profiles`, `visibility`, `status`, `room_version bigint`, `config_revision bigint NOT NULL DEFAULT 0`, `time_control int`, `current_match_id uuid NULL` (FK thêm ở TK05.1.3), `current_chat_context_id uuid NULL` (FK thêm ở TK05.2.1), `watch_epoch bigint NOT NULL DEFAULT 0`, `finished_at timestamptz NULL`, `created_at`.
```sql
CHECK (char_length(name) BETWEEN 1 AND 60)
CHECK (visibility IN ('PUBLIC','CODE_ONLY','LOCKED'))
CHECK (status IN ('WAITING','PLAYING','FINISHED','CLOSED'))
CHECK (time_control IN (0,300,600,900))
CHECK (room_version >= 0 AND config_revision >= 0 AND watch_epoch >= 0)
```
Index sảnh (partial): `(created_at DESC, id DESC) WHERE visibility='PUBLIC' AND status IN ('WAITING','PLAYING')` — **không** gồm FINISHED (`DEC-023`).

### 5.2 `room_members`
Cột: `room_id`, `user_id`, `membership_id uuid NOT NULL UNIQUE`, `role`, `side`, `ready boolean NOT NULL DEFAULT false`, `ready_revision bigint NOT NULL DEFAULT 0 CHECK (ready_revision >= 0)`, `ready_config_revision bigint NULL`, `joined_at`.
```sql
PRIMARY KEY (room_id, user_id)
CHECK (role IN ('PLAYER','SPECTATOR'))
CHECK ((role='PLAYER' AND side IS NOT NULL AND side IN ('RED','BLACK')) OR (role='SPECTATOR' AND side IS NULL))
CHECK ((ready AND ready_config_revision IS NOT NULL) OR (NOT ready AND ready_config_revision IS NULL))
CHECK (role='PLAYER' OR NOT ready)
ALTER TABLE room_members ADD CONSTRAINT room_members_side_uniq UNIQUE (room_id, side) DEFERRABLE INITIALLY DEFERRED;
```

### 5.3 `room_blocks` và `user_active_room`
- `room_blocks(room_id, user_id, blocked_by, blocked_at)`, `PRIMARY KEY (room_id, user_id)` — người bị đuổi.
- `user_active_room(user_id PK, room_id)` — **một tài khoản một phòng**.

### 5.4 `invitations`

| Cột | Ràng buộc |
|---|---|
| `id` | uuid PK |
| `room_id` | NOT NULL FK rooms |
| `issuer_id` | NOT NULL FK profiles |
| `recipient_id` | FK profiles; **DIRECT bắt buộc, CODE/LINK phải NULL** |
| `kind` | CHECK IN ('CODE','LINK','DIRECT') |
| `grant_role` | CHECK IN ('PLAY','WATCH') |
| `secret_hash` | DIRECT phải NULL; CODE/LINK NOT NULL; UNIQUE khi khác NULL; **không** có cột mã/token gốc |
| `status` | NOT NULL CHECK IN ('PENDING','CONSUMED','REJECTED','REVOKED','EXPIRED') |
| `watch_epoch` | WATCH bắt buộc ≥ 0; PLAY phải NULL |
| `created_at`, `expires_at` | NOT NULL, `CHECK (expires_at > created_at)` |
| `consumed_at` | nullable |

Index: `(recipient_id, status, expires_at)` (hộp thư); `(room_id, grant_role, watch_epoch, status)` (thu hồi); partial UNIQUE `(issuer_id, recipient_id, room_id, grant_role) WHERE kind='DIRECT' AND status='PENDING'`. FK dùng `RESTRICT`.

## 6. BẪY DỄ GẶP

| Bẫy | Hậu quả | Cách tránh |
|---|---|---|
| `UNIQUE (room_id, side)` không DEFERRABLE | Tái đấu đổi bên luôn lỗi giữa chừng | 5.2 |
| `side IN (...)` không kèm `IS NOT NULL` | PLAYER không có bên vẫn lọt | Viết tường minh |
| Lưu mã phòng gốc | Lộ DB = lộ quyền vào mọi phòng | Chỉ `secret_hash` |
| Index sảnh gồm FINISHED | Sảnh hiện phòng đã xong (sai `DEC-023`), index phình | Partial index |
